# 通用文档审查检查清单

## 基础检查
- [ ] 文档有明确标题
- [ ] 文档有版本/日期/作者信息
- [ ] 文档结构清晰（有目录或章节，层级不超过 3 层）
- [ ] 术语使用一致（术语首次出现有定义）
- [ ] 格式规范统一（标题层级、代码块语言标注、列表缩进）

## 内容完整性
- [ ] 覆盖所有需求/功能点（含异常路径）
- [ ] 有明确的验收标准（可量化、可验证）
- [ ] 有错误处理说明（每种异常有处理策略）
- [ ] 有边界条件说明（空值、极值、并发、超时）
- [ ] 有假设与约束声明

## 清晰度
- [ ] 无歧义表述（避免"可能""大概""适当"等模糊词）
- [ ] 关键概念有解释或引用（新人可理解）
- [ ] 图表与文字一致（架构图/流程图/序列图与描述不矛盾）
- [ ] 缩写首次出现有全称

## 环境准备
- [ ] 依赖列表完整（含版本号、安装命令）
- [ ] 环境变量配置完整（含 .env.example、变量说明、获取方式）
- [ ] 外部服务依赖明确（连接方式、健康检查、降级策略）
- [ ] 环境验证命令可执行（一键验证，有预期输出）
- [ ] 平台差异说明（如涉及多平台）

## 可执行性
- [ ] 步骤可操作（不是"理解""分析"等认知动作）
- [ ] 每个步骤有验证命令或预期结果
- [ ] 有回滚方案（如涉及不可逆操作）
- [ ] 有故障排查指南（常见问题与解决方法）
- [ ] 时间/资源预估（量级级别即可）

## 向后兼容与迁移
- [ ] 破坏性变更已标注并说明影响范围
- [ ] 数据迁移方案（如涉及，含回滚）
- [ ] API 版本策略已说明
- [ ] 弃用项有明确的替代方案和移除时间表
